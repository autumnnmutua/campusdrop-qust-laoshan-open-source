# 服务可靠性、交接与账号恢复

## 错误响应和连接恢复

所有 API 响应附带 `X-Request-Id`；错误 JSON 包含同一 requestId，可用于反馈定位。已知业务约束冲突返回409；识别到的数据库短暂不可用返回503，其余未知异常返回500。未知异常只记录固定分类、规范化路由、HTTP方法、状态及问题编号，不存原始异常、堆栈、query、Cookie、密码、恢复码、电话或取件码。

超级管理员可在 `/admin/errors` 查看最近100条错误与24小时分类计数。数据库最多保留1000条、7天；日志清理、过期限流记录和恢复码清理每天03:17 UTC执行。记录数据库失效时只保留固定字段的运行时日志，不让监控错误覆盖原始响应。

前端对GET/HEAD的网络错误、502/503/504最多重试两次，每次最多15秒；写请求不会自动重发。支付/注册结果不确定时提示查询已有结果。过往没有问题编号的500不能事后确定根因，本次不将推测标注为已定位。

限流窗口改为针对单条key的原子过期复位，避免先删除全部过期记录再写入的竞争窗口，减少每次请求的全表清理。用户不能用重试绕开限流。

## 交接申请

- 申请人可 `PATCH /admin/orders/:id/handoffs/:handoffId` 修改待核验申请，使用 handoffSchema（version、confirmed、location、note）。
- 有订单权限的非申请人 SUPER/ZONE/BUILDING 管理员可 `POST .../:handoffId/reject`，使用 releaseSchema（version、confirmed、reason）。
- 修改前的内容保存在handoff_changes，授权管理员可在交接修改记录查看；公共错误监控与审计metadata不含正文。
- 修改/驳回增加订单版本，持旧版本的核验被拒绝。已核验或已驳回记录不可改写。
- 驳回保留原申请和原因，解除待核验锁；包裹仍由原配送员保管，不能直接取消退款或退单。更正后提交新的申请，再由其他管理员核验。
- 数据库存储rejected标记以兼容历史PENDING/CONFIRMED约束，API将其展示为REJECTED。核验和驳回在数据库竞争时只能成功一个。

## 账号找回

不使用未验证手机号作为重置凭据，不提供客户端指定userId即可改密码的接口。

- 本人登录后在资料页“设置账号恢复码”验证当前密码，调用POST /me/recovery-code或/admin/me/recovery-code；有效30天，仅显示一次。
- 忘记密码后进入/recover，提交账号类型、用户名、恢复码及新密码到POST /auth/recovery/reset。
- 没有本人恢复码时，超级管理员在/admin/recovery独立核验本人身份并再次验证自己的密码，向POST /admin/recovery/issue提交kind、username、currentPassword、identityVerified:true，签发有效15分钟的恢复码，需通过可信私密渠道交付。
- 普通管理员不能签发；该管理接口不能重置其他SUPER_ADMIN。超级管理员使用自己的恢复码；若未保存恢复码，必须由持有云账户权限的运维人员执行受控离线恢复，不暴露公共后门。
- 恢复码32字节随机值，仅保存SHA256摘要，重新签发使旧码失效。密码重置、消费恢复码及撤销该账号所有会话由同一数据库更新触发器完成。
- 写入签发时再次检查签发人当前角色、密码和目标账号状态，防止预检后降权/改密的竞态。
- 学生新密码至少6字符，管理员至少12字符。恢复操作有限流，账号不存在/码失效/过期对公众统一回复。恢复不会修改原订单、角色或scope。

## 大规模分页

GET /orders、/admin/tasks、/admin/available支持pageSize与nextCursor；客户端把nextCursor作为下次cursor。每页最大100，市场默认30、界面12；订单界面20、任务界面30。

游标包含时间与ID作为稳定排序键，并绑定账号、列表和筛选条件。它不是授权凭据；每次查询仍重新校验所属用户/实时scope。修改筛选或账号后必须回到第一页。市场最早订单优先，学生与任务最新优先。

市场支持building、packageSize和deliveryMode组合筛选，过滤发生在数据库。查询只取本页加一条判定hasMore，不计算全量count。旧page参数在订单/任务保留浅页兼容，超过100页要求游标，避免深offset扫描。列表在并发插入/删改时不提供事务快照，刷新第一页可获取最新数据。

索引由0007迁移追加。历史0001–0006不修改，保留原账户和演示订单。部署时先备份、在staging应用迁移并验证，再更新生产。

## 验证范围

本轮在独立本地数据上验证了1201条订单游标遍历（无重复、无遗漏）、跨账号/损坏游标拒绝、交接修改/驳回/重提/核验竞态、恢复码并发消费及会话撤销、权限拒绝和数据库故障脱敏。浏览器验证恢复流程、分页筛选和360px监控页面。验证脚本及凭据留在本机私有目录，不纳入公开源码。

可复现业务问题已有修复和守卫；公网TLS/代理中断仍可能发生，软件重试不等于保证网络永久无故障。若再次遇到500，请提供页面问题编号，通过错误监控定位，不发送密码或完整取件码。
