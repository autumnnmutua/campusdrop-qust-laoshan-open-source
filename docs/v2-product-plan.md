# CampusDrop v2.0 产品规划

本文档记录 v2.0 的产品决策：要解决的问题、新增的功能、优先级，以及刻意没有做的事情和原因。

## 一、现状与问题

v1.x 已经跑通完整的业务闭环：登记取件码、下单、模拟支付、配送员接单、交接核验、售后，以及管理端的授权与审计。走查整条链路后，主要问题集中在四个方面。

1. **录入成本高。** 取件码要从驿站短信里手动抄写。同学一次收到多件快递时，要把"填码 → 选站点 → 保存"重复好几遍。
2. **运营没有广播渠道。** 遇到暂停配送、恶劣天气、驿站调整等情况，管理员无法通知所有学生，只能等学生下单后再单独联系。
3. **服务质量看不见。** 订单完成后没有反馈环节，管理端只有按状态计数的数字，看不到趋势、楼栋分布和学生满意度，也就无从改进。
4. **产品缺少温度和记忆点。** 界面能用，但缺少让同学愿意回来、愿意分享的体验细节。

## 二、v2.0 功能清单

### 学生端

| 功能 | 解决的问题 | 说明 |
| --- | --- | --- |
| 短信识别取件码 | 录入成本 | 粘贴驿站短信，自动识别取件码和快递公司，可一次识别多条。识别只在浏览器本地进行，短信内容不上传。 |
| 批量登记 | 录入成本 | 识别出多个取件码时，一键全部登记。 |
| 备注快捷标签 | 录入成本 | 提供"放门口""到了打电话""易碎轻放"等常用备注，一点即填。 |
| 公告横幅 | 运营广播 | 首页顶部展示有效公告，按普通、提醒、暂停三个级别区分样式，学生可以关闭单条公告。 |
| 服务评价 | 服务质量 | 确认收货后可打 1–5 星，并选择标签、留下短评。每单只能评价一次。 |
| 我的配送足迹 | 留存与温度 | 在"我的寝室"页展示累计配送、完成单数、少跑驿站次数和成就徽章，数据全部来自真实订单。 |
| 运费计算器 | 透明度 | 在配送说明页选择大小件和配送方式，即可看到费用和升级差价。 |
| 常见问题搜索 | 自助服务 | 输入关键词即时筛选问答。 |
| 订单筛选 | 查找效率 | 订单列表可按"全部 / 进行中 / 已完成 / 已取消"切换。 |
| 新手引导 | 上手门槛 | 第一次访问时，用三步引导说明下单流程，之后可以在帮助页重新查看。 |
| 添加到主屏幕 | 留存 | 提供网页应用清单，手机浏览器可以把网站添加到桌面，像 App 一样打开。 |

### 动效与氛围

| 功能 | 说明 |
| --- | --- |
| 季节氛围粒子 | 默认随季节自动切换：冬季（12–2 月）雪花、春季（3–5 月）樱花、夏季（6–8 月）光斑、秋季（9–11 月）落叶。学生可以点击顶部的“氛围”按钮手动选择或关闭，选择保存在本机浏览器。鼠标靠近时粒子会避让，轻点页面会把附近的粒子吹散；标签页切到后台时自动暂停。管理端不显示粒子，保持工作区安静。 |
| 彩带庆祝 | 首次下单、确认收货、打赏成功时，屏幕上撒下一阵彩带。 |
| 全局提示 | 订单状态变化（如"已送到楼下"）和操作结果用轻提示告知，不再只靠页面里的一行小字。 |

以上所有动效都遵循系统的"减少动态效果"设置：开启后全部关闭，页面内容不受影响。

### 管理端

| 功能 | 说明 |
| --- | --- |
| 运营数据看板 | 包括今日订单、近 7 日订单、进行中、完成率、平均评分，近 14 日订单趋势，状态分布，楼栋订单排行，大小件与配送方式占比，以及最新评价。数据范围严格遵守管理员的授权范围。 |
| 公告管理 | 仅超级管理员可用：发布公告（可设置到期时间）、下线公告、查看历史公告。 |
| 导出任务 CSV | 把当前筛选的任务导出为表格，方便线下核对。 |

## 三、取舍说明

- **不做真实支付、不接入物流接口。** 现有设计明确不发生真实扣款，也不读取第三方物流账号。v2.0 保持这一边界，短信识别也只在本地处理。
- **不做预计送达时间。** 系统没有实时定位数据，给出预计时间等于编造承诺。
- **不做深色模式。** 现有样式里有大量直接写死的颜色值，强行改造风险高、收益低，放到后续版本系统性重构时再做。
- **评价不公开展示。** 评价只给管理端用于改进服务，学生之间看不到，避免对配送员造成公开压力。
- **成就徽章只奖励真实行为。** 徽章不设排行，不鼓励刷单。

## 四、数据与兼容

- 新增迁移 `0009_engagement.sql`，只新增 `announcements` 和 `order_ratings` 两张表，不修改任何已有表和数据。
- 新接口全部沿用现有的会话、Origin 校验、限流和授权范围机制。
- 公告和评价相关请求失败时，前端会静默降级，不影响下单主流程。

## 五、实现说明

| 模块 | 位置 |
| --- | --- |
| 数据迁移 | `migrations/0009_engagement.sql`（`announcements`、`order_ratings` 两张新表，以及“只能评价自己已完成订单”的触发器） |
| 共享校验与类型 | `src/shared/engagement.ts`（公告与评价的 zod 校验、徽章规则、短信取件码识别） |
| 后端接口 | `src/worker/engagement.ts`：`GET /announcements`、`GET /me/stats`、`GET/POST /orders/:id/rating`、`GET /admin/analytics`、`GET/POST /admin/announcements`、`POST /admin/announcements/:id/archive` |
| 动效引擎 | `src/client/effects.ts`（季节粒子、彩带、全局提示）、`src/client/effects-ui.tsx`、`src/client/styles/features-shell.css`（样式已按层拆分，见 `src/client/styles/index.css`） |
| 学生端功能 | `src/client/engagement-ui.tsx`（公告横幅、短信识别、备注标签、费用计算器、问题搜索、配送足迹、评价、新手引导） |
| 管理端功能 | `src/client/admin-insights.tsx`（数据看板、公告管理）、`src/client/csv.ts`（任务导出） |

几处实现细节：

- 未执行 0009 迁移时，公告、评价和统计的读取接口按“暂无数据”返回，不影响下单；发布公告或提交评价会提示“需要先完成数据库升级”。
- 数据看板只统计已支付订单，并沿用任务列表的授权范围；日期按北京时间（UTC+8）划分。平均配送时长取近 30 天订单从“待取件”到“已送达”的状态事件时间差。
- CSV 导出不包含学生电话和取件码，并对以 `=`、`+`、`-`、`@` 开头的单元格做转义，防止表格公式注入。
- 所有动画在系统开启“减少动态效果”时停止；粒子画布在这种情况下不会创建。

## 六、v2.1 补充

v2.0 上线前的走查里还剩下几个“用起来不顺手”的地方，v2.1 集中补上：

| 功能 | 解决的问题 | 说明 |
| --- | --- | --- |
| 到达提醒 | 下单后要一直开着页面盯进度 | 学生自愿开启后，页面切到后台时仍以较慢频率（每分钟）检查订单，状态变化时弹出浏览器系统通知。没有服务端推送，需要网页仍然开着；部分手机浏览器只允许已添加到主屏幕的网页发通知，界面会如实提示。 |
| 配送凭证 | 学生需要留存记录 | 订单详情可打开打印友好的凭证页，打印或另存为 PDF。明确标注为模拟支付记录，不是发票。 |
| 再来一单 | 重复下单要重新选择 | 已完成、已取消订单可一键带入上次的大小件和配送方式。 |
| 复制取件码 | 去驿站时要翻找取件码 | 包裹卡片上一键复制。 |
| 表单草稿 | 填到一半切页面会丢 | “添加快递”表单自动保存到当前标签页，保存成功后清除。 |
| 快捷搜索 | 页面越来越多，入口不好找 | Ctrl/⌘ + K 或顶部“搜索”唤起，支持中文与拼音关键词，也能直接切换氛围动效。 |
| 网络状态提示 | 断网时操作失败原因不明 | 浏览器报告离线时顶部显示提示，恢复后提示一次。 |
| 新徽章庆祝 | 徽章获得后没有反馈 | 进入“我的寝室”时，本机首次看到的新徽章会弹出提示并撒彩带。 |
| 时段问候 | 首页缺少温度 | 首页按本机时间显示“早上好 · 日期”。 |
| 看板时间范围与热力图 | 只能看固定 14 天，排班没有依据 | 看板支持近 7 / 14 / 30 天，新增“星期 × 小时”下单热力图（北京时间），可导出 CSV。 |
| 新订单提醒 | 配送员要手动刷新接单市场 | 待接订单第一页每 30 秒自动刷新，有新订单时弹出提示，并在浏览器标签标题上显示数量。 |
| 404 小游戏 | 走错页面时体验生硬 | 404 页和 `/play` 提供“接包裹”小游戏，最高分只存在本机，不连接任何接口。 |

v2.1 **没有新的数据库迁移**，只在 v2.0 的 `/api/v1/admin/analytics` 上增加了 `days` 参数（7、14、30）和 `heatmap` 字段。

## 七、v2.2 补充

v2.2 先做了一轮系统排查（代码审查、axe 无障碍扫描覆盖全部学生端和管理端页面、桌面与 360px 手机宽度、控制台告警），修复项见 `CHANGELOG.md`。新增功能的取舍如下：

- **超时预警只给管理端。** 阈值（`STALL_RULES`）是团队内部的运营目标，不向学生展示，避免变成对送达时间的承诺。状态停留时间取该状态最近一次进入的事件时间，没有事件记录时退回订单更新时间。
- **配送员表现不做排行榜式的公开展示。** 表格只在数据看板里给有权限的管理员看，前三名标记只是方便阅读；评价本身仍然只对管理员可见。
- **分享卡片只放可以公开的信息。** 卡片在浏览器里本地生成，不上传服务器，只包含数量和徽章名称。
- **常用备注保存在本机。** 不新增服务端字段，换设备不会同步，界面上会说明。
- **彩蛋和小游戏不影响业务。** 它们不调用任何接口，系统开启“减少动态效果”时彩带不会播放。

## 八、v2.3 补充

甲方在 v2.2 之后提出两项需求：识别截图里的取件码，以及加入文字跳动效果。

- **截图识别在本机完成。** 这和短信识别保持一致：截图里往往还有其他私人信息，上传到服务器既增加隐私风险，也需要额外的识别服务费用和账号配置。代价是首次使用要下载约 7 MB 的识别引擎，并且只识别数字和拉丁字母（中文模型约 20 MB，对“提取取件码”帮助不大）。识别结果不会直接登记，而是进入同一个核对列表，由学生确认后再登记。
- **文字跳动只用于“值得注意的时刻”。** 详见 `docs/text-bounce-design.md`：品牌标题、状态变化、成功时刻和轻松场景使用，需要仔细阅读的内容和管理端不使用；提供开关，并遵循系统的“减少动态效果”设置。
- **配送路线单不印电话和取件码。** 纸质单据容易遗失，这两项信息仍然只在系统内查看。
